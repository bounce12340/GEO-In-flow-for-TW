# 抓取目的分析：這個 AI 為什麼來？

位置：網站分析 → AI 蜘蛛歸因與控制 → 「抓取目的」分頁。程式：`src/lib/liekan/crawlers/purpose.ts`（純函式，含單元測試）、`src/components/liekan/features/CrawlPurposePanel.tsx`。

## 判定原則

目的由**爬蟲目錄中已審核的身份**決定，不從單一請求猜測。一筆請求先依 UA token 對應到目錄身份，再由該身份在營運方文件中的用途決定目的：

| 目的 | 白話說明 | 來源 |
| --- | --- | --- |
| 訓練抓取 | 營運方收集網頁用來訓練或改進 AI 模型。允許與否不直接影響 AI 搜尋中的引用。 | 目錄類型 training；CCBot、AI2Bot 另標記為開放資料集 |
| AI 搜尋索引 | 為 AI 搜尋或問答產品建立索引；允許造訪通常是被 AI 回答引用的前提。 | 類型 search |
| 使用者即時觸發 | 使用者在 AI 產品中提問或貼上網址時，AI 即時讀取頁面。營運方普遍說明可能不遵循 robots.txt。 | 類型 user |
| Agent 代理瀏覽 | AI Agent 代替使用者瀏覽並可能執行操作。 | 簽章 Agent（如 ChatGPT agent）；`Google-Agent` 併入目錄後亦歸此類 |
| 傳統搜尋 | 搜尋引擎索引。Google 的 AI 摘要與 AI 模式使用 Googlebot 索引，沒有額外要求；Bing 索引也支撐 Copilot。 | 類型 traditional_search |
| 其他 | 廣告檢查、SEO 工具、連結預覽、研究或通用抓取。 | 類型 other |
| 無法判定 | 請求沒有對應到已審核身份。只憑 UA 無法得知營運方或目的，所以不推斷。 | 未登記或自訂規則 |

限制：目的反映營運方公開說明的用途，不代表該次請求實際被如何使用；同一身份可能兼具多種用途（例如 Amazonbot），以目錄主要類型計算。

## 分頁內容

1. **抓取目的總覽**：各目的的請求數、占比、身份數與說明。
2. **各身份目的與來源**：爬蟲、地區（台灣、全球 / 美國、日本、韓國、歐洲、中國大陸）、目的、資料集曝光標記、請求數與來源連結（目錄記錄的來源，可能是營運方官方文件，也可能是觀察資料，例如 Meta、Bytespider 依據 Cloudflare 的觀察）。
3. **內容類型與目的**：依路徑副檔名分類（網頁、文件、圖片、音視訊、資料 / API、網站地圖 / 訂閱、robots.txt、llms.txt、AI 政策檔、靜態資源）。日誌不含 Content-Type，因此以路徑判斷。
4. **頁面與目的（前 100）**：哪些頁面吸引哪些目的與爬蟲。
5. **讀取 robots.txt / llms.txt 的爬蟲**：`/robots.txt`、`/llms.txt`、`/llms-full.txt`、`/ai.txt`、`/.well-known/tdmrep.json` 的讀取者與成功次數。
6. **robots.txt 遵循檢查**：若最近一次「公開頁面檢查」已讀取 robots.txt，會直接使用；也可以貼上 robots.txt 內容（只在瀏覽器內比對，不會儲存）。系統用既有的 RFC 9309 解析器，逐筆比對有 robots token 的身份所抓取的路徑，列出命中 Disallow 的請求。沒有 robots.txt 時顯示「無法判斷」。使用者觸發的獲取器命中禁止路徑不一定代表違規。
7. **使用者觸發獲取與 AI 引薦造訪**：同一平台（例如 OpenAI）的使用者觸發抓取（ChatGPT-User）與該平台 AI 引薦落地頁，在同一期間出現在同一頁面時標為「兩者皆有」。這是**共同出現，不是因果**；資料為期間彙總，無法判斷先後順序。引薦資料缺少輸入或瀏覽身份不可用時顯示「待接入」。

## 資料來源與範圍

全部使用既有的 crawler-analysis 快照（同一範圍、身份口徑與截斷規則），沒有新增資料表或查詢，也不產生任何假資料。頁面紀錄上限為 1000 條路徑，超出時會顯示截斷提示。
